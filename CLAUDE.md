# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static Jekyll website for the Gereformeerde Gemeente Emmeloord (a Dutch church), hosted on GitHub Pages. Design (brown header bar, overlapping circular logo, cream background, serif type) is based on the church's presentation slide deck, not a generic theme.

## Commands

```sh
bundle install          # install Jekyll + plugins (github-pages gem pins versions to match GH Pages)
bundle exec jekyll serve  # local dev server at http://localhost:4000, live rebuild
bundle exec jekyll build  # production build to _site/
```

There is no test suite and no linter configured. Deployment is just `git push` to `main` — GitHub Pages builds and publishes automatically; there is no separate CI step to trigger.

## Architecture

**Templates**: every page uses `_layouts/default.html`, which pulls in `_includes/header.html` and `_includes/footer.html`. There's only one layout — no per-section layout variants. Both the logo badge and the site title in the header bar are links to the homepage (Joan wants the title clickable, not just the logo).

**Styling**: all CSS lives in `assets/css/style.scss`, with the color palette defined once as CSS custom properties at the top (`--brown`, `--brown-dark`, etc.). Changing the brand color means editing those variables *and* the hardcoded fill in `assets/img/logo.svg` (see below) — the SVG can't reference CSS variables, so the two are manually kept in sync.

**Logo badge**: `assets/img/logo.svg` is not just the church logo — it's a three-layer badge built to match the slide design: an outer circle filled with the same brown as the header bar (`--brown`, `#8f6c55`), a white disc inside it, and the traced church glyph scaled to 80% inside that. On desktop the header CSS (`.logo`, `.header-bar` in `style.scss`) positions this badge absolutely with a negative `left` offset so it overlaps the bar's rounded corner without leaving a sliver of the bar visible behind it — that offset is empirically tuned, not derived from a formula, so re-check visually after touching either the badge size or the bar's `border-radius`. **On mobile (≤640px) the overlap is deliberately gone**: the badge sits as a normal flex item fully inside the bar (the overlap looked broken on a short bar — "logo out of bounds"), sized 48px, 42px at ≤360px. The mobile title font caps (`clamp` max ~1rem, 0.92rem at ≤360px) are tuned so "Gemeente Emmeloord" stays on one line and the title wraps to exactly two lines next to the logo, login icon, and hamburger — verified by headless-Edge screenshots at 390/360/320px; below ~330px it falls back to three lines, which is accepted.

**Three features resolve client-side, not at Jekyll build time** — all exist to work around GitHub Pages only rebuilding on `git push`:

- **Mededelingen (time-boxed homepage announcements)**: markdown files in `_mededelingen/` (a Jekyll collection with `output: false`, so they're data, not published pages) carry `vanaf`/`tot` dates in front matter. `index.md` renders all of them into the page, hidden, with `data-vanaf`/`data-tot` attributes. `assets/js/mededelingen.js` runs in the visitor's browser and un-hides only the ones whose date window includes "now". This means an expired announcement disappears without anyone pushing a commit on the end date — but also means expired/future announcements still exist in the page's HTML source (not secret, just not displayed). Each card carries an uppercase "Mededeling" kicker (`.mededeling-kicker`, real markup in `index.md`, not CSS `content`) and a white background so it pops against the cream page — Joan explicitly asked for the pop; don't quiet these down.
- **Uitzending-knop (freely watchable livestream)**: same date-window mechanic, separate collection `_uitzendingen/` (`titel` = the livestream's name and the literal button text, `stream_url`, `vanaf`/`tot`) rendered by `index.md` as a single-line button above the mededelingen, shown/hidden by `assets/js/uitzending.js`. Styling is brick red (`--brick`/`--brick-dark`, the only red on the site) with a **deliberately subtle** 1%-scale pulse on hover only (`uitzending-puls`; the global reduced-motion rule disables it). Otherwise minimal per Joan: one line, only the name, no date/time shown — he rejected a richer banner design, so don't add info or decoration back. The inline play-icon SVG in `index.md` carries explicit `width`/`height` attributes as a fallback: a stale cached stylesheet once rendered it page-filling huge.
- **Agenda (iCal feed on the Diensten page)**: `assets/js/agenda.js` fetches the URL in `_config.yml`'s `ical_feed` directly from the browser and parses VEVENTs with a small hand-rolled ICS parser (`webcal://` is rewritten to `https://` since `fetch()` rejects that scheme; RRULE recurrence is *not* expanded, only literal events). This only works if the feed server sends `Access-Control-Allow-Origin`, since it's a cross-origin browser fetch, not a server-side build step. The feed currently referenced is the HVC-afhaalkalender FastAPI app (`bin.zandijk.xyz`, a separate repo/project on the NAS) — that app's `main.py` has CORS middleware added specifically to support this. `ical_feed` is presently empty/commented out in `_config.yml`; the agenda section self-hides whenever it's empty.

**Mobile nav**: the hamburger menu is a pure-CSS checkbox hack (`#menu-toggle` input + its `<label>` in `_includes/header.html`), deliberately not JS-driven — navigation has to keep working even if scripts fail to load, unlike the two features above. `.site-nav` is toggled via `.menu-toggle-input:checked ~ .site-nav` in `style.scss`, which requires the input and the nav to be *siblings* (both direct children of `<header>`) for the `~` combinator to reach across `.header-bar` in between. The "Inloggen" button (`.nav-login`) lives once, in the header bar: full pill with text on desktop, shrunk by the `@media (max-width: 640px)` block to a circular icon-only button next to the hamburger (the text `<span>` stays in the markup but is clipped sr-only-style, so screen readers still get a name). An earlier version duplicated the button inside the mobile dropdown (`.nav-login--menu`), which forced every `.site-nav a` rule to be written as `.site-nav a:not(.nav-login)` to avoid a specificity clash that once rendered the button brown-on-brown — that duplicate and the `:not()` exclusions are gone; don't reintroduce a `.nav-login` inside `.site-nav` without remembering that trap.

**Sticky header backdrop**: `.site-header` is transparent on all breakpoints — the brown bar (and on desktop the nav pill) "float" over scrolling content. A solid cream mobile backdrop was tried and explicitly rejected by Joan; don't reintroduce it. The mobile dropdown menu uses the same frosted treatment as the desktop pill (translucent cream + `backdrop-filter: blur`), not opaque white.

**Gotcha — kramdown vs multi-line span-level HTML**: in any markdown-processed context (page body, or inside `<div class="page" markdown="1">`), a span-level element like `<a>` written across multiple lines gets mangled by kramdown — the anchor is closed early and the trailing `</a>` appears as literal page text (this shipped once: the uitzending button rendered as an empty red bar with "`</a>`" below it). Block-level elements (`div`, `section`, `article`) pass through untouched (`parse_block_html` is off), so either wrap custom markup in a block wrapper (the uitzendingen `<div>` in `index.md` exists for exactly this reason — don't remove it) or keep the anchor on one line (the kaart link in `contact.md`). Raw-HTML previews don't catch this class of bug; it only appears in Jekyll's rendered output.

**Gotcha — generic `a:hover` vs white-text link components**: the global `a:hover { color: var(--brown-deep) }` rule (element+pseudo-class specificity) beats any bare single-class color like `.nav-login` or `.skip-link`, turning white text brown-on-brown on hover — this is the same specificity trap as the retired `.site-nav a:not(.nav-login)` story, resurfacing via `a:hover`. Every component that puts white text on a brown background must set its own explicit hover color (`.nav-login:hover`, `.skip-link:hover`, `.site-title a:hover` all do). Check this whenever adding such a component or a new generic `a...` rule.

**Hamburger checkbox tab order**: `.menu-toggle-input` is `display: none` at the base (desktop shows no hamburger, so a focusable invisible checkbox would pollute the tab order) and is restored inside the ≤640px media query as visually-hidden-but-focusable (`position: absolute; 1px; opacity: 0`). Both halves are needed: removing the mobile restore breaks keyboard access to the menu; removing the desktop `display: none` puts a ghost tab stop back.

**Map on the contact page**: `assets/img/kaart.png` is a static, self-hosted map (OSM tiles stitched offline, brick-red pin on the Moriakerk at 52.7176, 5.7455) — no embed, no external requests, no cookies. It links to Google Maps directions; the "© OpenStreetMap-bijdragers" attribution line under it is a license requirement, don't remove it. Regenerating means re-stitching tiles, not editing the PNG.

**Installable icons/manifest**: `manifest.json` (Jekyll-processed for `baseurl`-aware paths, like `robots.txt`) plus `assets/img/icon-192/512.png` (transparent, rendered from `logo.svg`) and `apple-touch-icon.png` (cream background, as iOS composites its own corners). If the logo changes, all three PNGs must be re-rendered from the SVG.

**Images**: `hero.jpg` is deliberately kept web-sized (1920px wide, JPEG q70, ~140KB — it sits under a dark overlay so compression artifacts are invisible); never commit a camera-original here (one was once committed at 3.3MB). `og.jpg` (1200×630, ~60KB) is the site-wide social-preview image, wired up via `defaults` → `image` in `_config.yml` (jekyll-seo-tag turns it into `og:image`) — WhatsApp and other messengers won't show previews for multi-MB images, which is why it's a separate small file. Address/e-mail live once in `_config.yml` (`address`, `email`) and feed the footer and the `Church` JSON-LD in `_layouts/default.html`; the contact page repeats them in prose.

**Hero background**: `.hero`'s `background-image` reads a CSS custom property `--hero-bg` with a gradient fallback (`style.scss`). `index.md` sets that property inline only when `site.hero_image` (in `_config.yml`) is non-empty, layering a fixed dark overlay under the photo so `.hero-box`'s white text stays legible regardless of the image's content — the same override-a-CSS-var-from-Liquid pattern as the login button's conditional rendering.

**SEO**: handled by the `jekyll-seo-tag` and `jekyll-sitemap` plugins (both included via the `github-pages` gem, no extra install needed) — `{% seo %}` in `_layouts/default.html` generates title/description/canonical/OG/JSON-LD tags, and `jekyll-sitemap` generates `/sitemap.xml`, which `robots.txt` points to.

**Canonical domain**: `url`/`baseurl` in `_config.yml` currently point at the GitHub Pages project URL (`kathedra.github.io/gergememmeloord`), not the eventual real domain `gergememmeloord.nl` (which currently serves a different, older Carrd site). Both values need to flip together if/when this Jekyll site takes over that domain — there's a comment in `_config.yml` marking the two lines to change.
